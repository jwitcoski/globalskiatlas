      How one resort job runs
      1. 1 Docker container starts on the home PC
      2. 2 Python takes the next task from the job list
      3. 3 Pull OpenStreetMap (outline, trails, lifts)
      4. 4 Pull Mapzen Skadi 1″ (~30 m) terrain tiles from AWS
      5. 5 Write resort files (stats, cropped DEM, 3D scene)
      6. 6 Publish status.json to the website bucket about once a minute
      7. 7 CloudFront serves this page

      AI writing

      Two home PCs write English resort pages from search notes, splitting a 499-region queue (even/odd), United States first.

      About this pipeline

      An Asus PB60 mini PC (Core i5-9500T, 8 GB DDR4, bought for $60) runs the sweep at home. It walks 373 regions one at a time; a full lap takes days. OpenStreetMap supplies boundaries, trails, and lifts. Terrain is Mapzen Skadi 1 arc-second tiles from AWS. This page is a work log, not a storefront.

      Definitions

      • Queued to add — on the waiting list; nothing has been built yet.
      • Updated — the resort already existed and was rebuilt from current map data.
      • Failed — no downhill run long enough to publish, the region cannot be determined, or another error. The sweep continues.
      • Systemic / network — the same infrastructure error across many resorts (for example DNS).
      • Per-resort failure — a genuine skip for that mountain (no publishable run, unknown region).
      • Complete (AI) — a page was written.
      • Insufficient data (AI) — search did not gather enough notes, so no page.
