Harvested resort facts

Every chip, price, and total on this page is a value stored in atlas-ResortFacts, or it is marked unknown. The table is empty until the copy harvest is pushed.

What this page counts

Harvested facts are comparable attributes written into one DynamoDB table, atlas-ResortFacts, in us-east-1. They feed the filter chips, the profile line, the price line, and the totals above. They are not the resort article. A sentence in the wiki body is not copied down into a chip. Trail length, lift count, and vertical drop stay on the resort wiki page, which reads atlas-WikiPages and the OpenStreetMap extract. This page does not reprint those figures as if the harvest had measured them.

Each row is one winter sports area. The key is winterSportsId, the OpenStreetMap id of the landuse=winter_sports feature, the same id the wiki page stores. pageId, when the harvest stored one, is the wiki slug. Name, country, and state appear only when a source supplied them. State is often missing outside the United States, and a missing state is unknown rather than a blank country. Tier is small, medium, or large when a size was stored. updatedAt is the last time that row was written.

Unknown is not no

A missing attribute is unknown. Filters and percentages both follow that rule. An amenity chip turns solid only when the stored value is boolean true, or the word yes when a source used that word. Boolean false and the word no mean a source said the hill does not have that thing. Those rows stay in the no count. Rows that never received the attribute are left out of the percentage and stay visible as grey chips.

The night-skiing share is the count of stored yes values divided by stored yes plus stored no. Unknown rows are on the page so you can see them, and they are not in the denominator. A filter for night skiing keeps rows where that attribute is true. It does not hide unknown rows by treating them as false, and it does not list the hills a source marked no. Leaving the chip off means you are not filtering on that amenity. It does not mean you asked for hills without it. There is no “is false” filter here, because the harvest question this page answers is which hills a source marked as having the feature.

Amenities

The boolean fields are snowtubing, ski rentals, ski instructors, night skiing, terrain park, nordic, childcare, snowmaking, and glacier. Grey text with the word unknown is the empty state. An outlined chip that starts with “No” is a stored false. Those two states are not interchangeable. A resort can be famous for night skiing in a brochure and still be unknown here until a source note is stored on the row.

Passes

Passes are a string set. One resort can be on Ikon and a local pass at the same time. The canonical labels are Epic, Ikon, Indy, Mountain Collective, Power Pass, and Nord Pass. Any other stored text is kept as a local name. An empty set, or no passes attribute, means the harvest does not know, or the source was a mega-pass roundup that did not name this hill. This page does not guess a pass from the resort’s reputation.

The pass mix counts three groups inside the current filter: Ikon and no local name, a local name and no Ikon, and both. The share for each group uses only those three counts. Resorts stored with a canonical pass other than Ikon, such as Epic alone, are listed as other. They are not called local. Resorts with no pass data are counted as unknown and left out of the three shares. Set the state filter to Vermont and apply when you want that mix for Vermont rows only. The totals follow the filter. They are not a separate statewide report hiding under a different country.

Prices

The price chip prints lift_ticket_raw as it was stored. A day ticket written as 49 EUR stays 49 EUR. A day ticket written as $34.00 CAD (day) stays in Canadian dollars, with the day note still attached. The page does not run a conversion on that string. lift_ticket_amount and lift_ticket_currency are the parsed pieces when the harvest stored both. They are labeled as a parsed amount so they are not mistaken for a second, converted price. If either piece is missing, the parsed line is omitted.

lift_ticket_usd is a stored number used for the median and for sorting inside the dataset. It is not the price chip. The median is the middle lift_ticket_usd among rows in the filter that have that number, grouped by the stored country. Rows with no USD figure are skipped. A country with no USD values is absent from the list. That absence is not a median of zero. When the count of USD values is even, the median is the mean of the two middle numbers.

Price band

The band is the label stored on the row. One dollar sign means at or under 50 USD a day. Two means over 50 through 100. Three means over 100 through 200. Four means over 200. The chip shows the stored band. It is not recomputed from the raw string, so a raw price in euros does not get relabeled by this page. Weekend, night, and season prices use the same rule: the raw string is shown when it exists, and the line is omitted when it does not.

The ticket links to the source URL stored for that price, when one exists. The tooltip is the evidence note. If the row has a USD figure and no raw string, the chip still says the ticket price is unknown.

Profile, access, and evidence

Profile text is omitted when the attribute is missing. That covers the official website, owner, operator group, operator status, year started, village type, visit type, what the hill is known for, and whether an on-hill lodge was recorded. Operator status is independent, club, not-for-profit, or some other phrase a source used. The website line is shown only for an http or https host that is not Wikipedia, TripAdvisor, or Booking. Those hosts are not treated as the hill’s own site, so a stored URL on one of them is left off the strip instead of being presented as official.

Access notes are optional text: drive, parking, season open, season close, sectors, and terrain. The same omit-if-missing rule applies. They are not amenity chips.

Evidence can sit beside a field. The harvest may store a source of ai or user, a source kind such as official, pass site, wikipedia, third party, user, or unknown, a source URL, a short evidence note, and a locked flag. Sign in to correct a cell. The save writes the value you submit, sets the locked flag, and marks the source as user. A locked cell is one the harvest is not supposed to overwrite. Clearing the value removes it and locks that absence, so a later harvest does not fill the gap. The save is rejected when the website host is not an official site, when a band or tier is outside the labels above, or when an amenity is something other than true, false, or cleared. A correction needs a row that already exists. This page does not create a resort.

Operations totals

copy_status is complete, insufficient_data, or skipped. It is not a public amenity. The totals include a count of insufficient_data by state so you can see where the harvest did not have enough notes. Note counts and search attempts stay off the chips. A state with no such rows is absent from that list. An empty table shows no gaps, and it shows the night-skiing share as unknown rather than 0%. Zero percent would claim that every stored answer was no. An empty table has no answers.

How a filter is read

Country, state, and the wiki slug use the matching index: country-index, state-index, or pageId-index. The primary key remains winterSportsId. Pass membership is a contains check on the passes set. An amenity filter is equality with true, and also with the word yes. Price band and tier are exact labels. Combining filters keeps a row only when every requested value is actually stored. Unknown never satisfies “has night skiing” or “on Ikon”.
